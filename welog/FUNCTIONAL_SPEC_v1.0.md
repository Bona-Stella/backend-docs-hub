# 🏥 WeLog (위로그) - V1.0 기능 명세서

> **WeLog**는 '위(Stomach)'와 '로그(Log)'를 합친 이름으로, 식습관 기록과 질병 발병 데이터를 분석하여  
> 오늘과 내일의 발병 확률을 예측해 주는 **위장 건강 관리 헬스케어 서비스**입니다.

---

## 1. 👤 회원가입 및 온보딩 (User Onboarding)
사용자의 진입 장벽을 낮추면서도, 서비스 이용에 필수적인 '건강 데이터'를 자연스럽게 수집하는 것이 목표입니다.

| 기능 구분 | 구현 목표 및 상세 내용 | 주요 UI/UX 스펙 | 비고 |
| :--- | :--- | :--- | :--- |
| **스플래시** | **브랜드 아이덴티티 전달**<br>- 앱 실행 시 로고 노출 및 초기 데이터 로딩 처리.<br>- 자동 로그인 여부 체크 후 화면 분기. | • `WELOG` 타이포 + 네온 로고<br>• 애니메이션: Fade In/Out | |
| **회원가입** | **단계별 입력 (Step-by-Step)**<br>- **Step 1 (계정):** 이메일/비밀번호 유효성 실시간 검증.<br>- **Step 2 (프로필):** 닉네임 설정 및 관리 질병 등록.<br>- **완료:** 이메일 인증 안내 모달 팝업. | • **유효성 시각화:** 충족 시 녹색 테두리 + 체크(✔) 아이콘<br>• **비밀번호:** 8자 이상, 특수문자 포함 조건 체크 UI | |
| **로그인** | **간편한 접근성**<br>- 이메일/비밀번호 기반 로그인.<br>- 비밀번호 표시/숨기기(Show/Hide) 토글 기능. | • 입력 필드 내 `👁️` 아이콘 제공<br>• 오류 시 Toast 메시지 출력 | 비밀번호 찾기는 V1.0 제외 → 비밀번호 재설정으로 변 |
| **초기 설정** | **개인화 데이터 수집 (질병)**<br>- 관리할 질병을 **태그(Chip)** 형태로 다중 선택.<br>- 목록에 없는 질병은 '직접 입력'으로 추가. | • **질병 칩:** 선택/미선택 상태 색상 반전<br>• **추가 버튼:** `[+ 추가]` 클릭 시 입력창 활성화 | 최소 1개 필수 선택 |

## 2. 🏠 메인 대시보드 (Dashboard)
사용자의 현재 위장 상태(종합 위험도)와 주의해야 할 세부 요인(Action Item)을 한눈에 파악하는 홈 화면입니다.

| 기능 구분 | 구현 목표 및 상세 내용 | 주요 UI/UX 스펙 | 비고 |
| :--- | :--- | :--- | :--- |
| **상태 대시보드** | **직관적인 위험도 시각화**<br>- 현재 관리 중인 질병의 위험도를 **원형 게이지(Circle Gauge)**로 표시.<br>- **질병 스와이프:** 좌우 스와이프로 다른 질병 상태 확인. | • **상태별 색상:**<br>🟢 **안전(0~20%):** Green<br>🟡 **주의(21~50%):** Yellow<br>🔴 **위험(51%~):** Red | 데이터 없을 시<br>`수집중 --%` 표시 |
| **날짜 전환** | **오늘/내일 상태 확인**<br>- 상단 탭(`오늘`/`내일`)을 통해 예측 시점 전환.<br>- 내일 확률은 야식 등 잔존 소화 시간 고려하여 계산. | • 탭 전환 시 게이지 및 하단 데이터 애니메이션 교체 | |
| **주요 위험 요인** | **행동 가이드 제공 (Top 3)**<br>- 현재 위험도를 높인 주범(태그/속성) 3가지를 카드 형태로 노출.<br>- **종합 상태와 별개로, 해당 요인의 기여도에 따라 경고 색상 표시.** | • **카드 UI:** 아이콘 + 텍스트 + 위험도(%)<br>• 클릭 시 해당 요인의 **상세 분석 페이지**로 이동 | |
| **기록 액션** | **빠른 기록 진입 (Floating)**<br>- 하단 `[+]` 버튼 클릭 시 **액션 시트(Action Sheet)** 호출.<br>- `[⚡ 아파요]` vs `[🍽️ 먹었어요]` 선택 분기. | • **아파요:** 즉시 기록 후 토스트 메시지<br>• **먹었어요:** 음식 기록 화면으로 이동 | |

## 3. 📝 기록하기 (Logging)
사용자의 입력 피로도를 최소화(Minimal Effort)하면서도, 분석에 필요한 핵심 데이터(사진, 태그, 시간)를 빠짐없이 수집하는 것이 목표입니다.

| 기능 구분 | 구현 목표 및 상세 내용 | 주요 UI/UX 스펙 | 비고 |
| :--- | :--- | :--- | :--- |
| **기록 진입** | **목적별 빠른 분기**<br>- 메인 `[+]` 버튼 클릭 시 액션 시트 노출.<br>- `[⚡ 아파요]` : 즉시 증상 기록.<br>- `[🍽️ 먹었어요]` : 음식 기록 화면 진입. | • **아파요:** 별도 화면 없이 토스트("기록 완료") 피드백<br>• **먹었어요:** Full Page 입력 폼 이동 | |
| **음식 기록** | **스마트한 입력 프로세스**<br>- **사진:** 갤러리/카메라 선택. (썸네일 리사이징)<br>- **메뉴명:** 텍스트 입력 시 **내 과거 기록 기반 자동완성** 제공.<br>- **재료:** `[+ 추가]` 버튼을 통해 해시태그 형태로 입력. | • **자동완성:** 입력창 하단에 검색 결과 리스트 노출<br>• **재료 칩:** 입력된 재료는 삭제 가능한 칩 형태로 나열 | |
| | **직관적인 속성 태그 (Chip Selection)**<br>- 맛, 온도, 상황 등 정해진 속성을 **버튼(Chip)**으로 빠르게 선택.<br>- 선택 시 즉시 시각적 피드백(반전/테두리). | • **카테고리:** 맛/자극, 온도, 상황 등 그룹핑<br>• **다중 선택:** 여러 속성 동시 선택 가능 | |
| | **메타 데이터 자동화**<br>- **시간:** 현재 시간 Default (수정 가능).<br>- **식당:** 선택 입력 (자동완성 지원).<br>- **야식 판별:** 입력 시간(22시~) 기준 `#야식` 태그 자동 부여. | | |
| **증상 기록** | **초간편 원클릭 (One-Tap)**<br>- 복잡한 입력 없이 버튼 클릭 한 번으로 `발병 시점` 기록.<br>- 실수 방지를 위한 `[실행 취소]` 기능 제공. | • **토스트:** "증상이 기록되었습니다. [실행 취소]" | |

## 4. 📊 분석 및 조회 (Analysis)
누적된 데이터를 기반으로 인과관계를 파악하는 페이지입니다.

| 기능 구분 | 상세 기능 | 사용자 경험 (User Flow) | 비고 |
| :--- | :--- | :--- | :--- |
| **피드(Feed)** | 타임라인 | 내가 기록한 음식/증상을 최신순 리스트로 조회.<br>각 기록별 위험도 점수 표시. | |
| **캘린더** | 발병일 확인 | 달력에 발병한 날짜가 🔴 표시됨.<br>날짜 클릭 시 해당 일자의 섭취/증상 기록 필터링. | |
| **차트 분석** | **유형별 위험도** | 3가지 관점의 독립적인 위험 확률(%) 제공<br>1️⃣ **메뉴별:** "이 메뉴 먹었을 때 얼마나 아팠나?"<br>2️⃣ **태그별:** "이 재료/속성일 때 얼마나 아팠나?"<br>3️⃣ **식당별:** "이 식당 갔을 때 얼마나 아팠나?" | |
| **수정/관리** | **계산 제외** | 특정 기록(예: 폭음)을 분석 로직에서 제외하는 기능. | 아웃라이어(이상치) 관리 |
