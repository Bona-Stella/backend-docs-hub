## 📌 프로젝트 개요 (WeLog)
**WeLog(위로그)**는 '위(Stomach)'와 '로그(Log)'를 합친 이름으로, 식습관 기록과 질병 발병 데이터를 분석하여 오늘과 내일의 위장 질환 발병 확률을 예측해 주는 헬스케어 서비스입니다.

## 📝 상세 작업 로그 (Change Log)

### [2026-01-13] v0.3.7 - 분석 대시보드 설계 및 캘린더 구현
- **작업 내용:**
  - **분석 대시보드(Analysis Dashboard) 전체 와이어프레임 확정:**
    - **레이아웃 표준화:** '헤더(기간/탭) → 컨트롤(위험/안심 토글) → 데이터(차트/리스트)'로 이어지는 공통 UI 구조 수립.
    - **네비게이션:** 상단 탭(종합/음식/태그/식당) 간의 일관된 이동 경험 및 스위치 위치 통일.
  - **종합 분석(Overview) 및 상세 UI 설계:**
    - **종합 요약 카드:** 위장 건강 점수(Score)를 시각화한 **도넛 차트(Donut Chart)**와 핵심 원인(시간+원인) 요약 문구 배치.
    - **상세 분석(Detail View) 컨셉:** 개별 항목(예: 마라탕)의 위험도를 직관적으로 보여주는 **히어로 카드(Hero Card)** 및 3분할 통계(기록/발병/최근) 레이아웃 적용.
  - **분석 캘린더(Calendar) UI/UX 구현:**
    - **버티컬 스크롤(Vertical Scroll):** 월(Month) 경계를 끊김 없이 넘나들며 기간을 선택할 수 있는 상하 스크롤 방식 채택.
    - **사용성 개선:** 매월 1일 날짜 위에 'N월' 텍스트를 표기하고, 스크롤 비중에 따라 상단 년/월 타이틀이 변경되는 스마트 헤더 로직 적용.
- **비고:**
    - **토글 인터랙션:** 카드 타이틀 우측에 '위험/안심' 텍스트 토글을 배치하여, 모드 전환 시 차트 데이터와 멘트가 동적으로 변경되도록 설계.

### [2026-01-11] v0.2.4 - 피드 상세 및 관리 기능 UI 디자인
- **작업 내용:**
  - **피드 상세 화면(Detail View) 디자인:**
    - 리스트 아이템 클릭 시 진입하는 상세 페이지 UI 구성.
    - 고해상도 음식 사진 뷰어, 전체 태그 목록(더보기 확장), 섭취 시간 및 연관 증상 표시 영역 설계.
  - **게시물 관리 메뉴(Context Menu) UI:**
    - 피드 카드 내 더보기(`...`) 버튼 클릭 시 노출되는 바텀 시트(Bottom Sheet) 디자인.
    - '기록 수정' 및 '삭제' 버튼 배치 및 오작동 방지를 위한 터치 영역 최적화.
  - **발병/증상 기록(Symptom Log) 시각화:**
    - 일반 음식 기록과 구분되는 증상 기록 전용 카드 스타일(붉은색 테두리/배경 강조) 적용.
    - 통증 강도 및 증상 아이콘을 타임라인 내에서 직관적으로 식별하도록 디자인 고도화.
  - **시스템 피드백 UI(Modal & Toast) 스타일링:**
    - **삭제 확인 모달:** 기록 삭제 시 실수 방지를 위한 경고 팝업 디자인 (Dark 테마 적용).
    - **토스트 메시지:** 작업 완료/취소 시 하단에 노출되는 플로팅 메시지 디자인 및 애니메이션 값 설정.
- **비고:**
    - **화면 전환:** 리스트에서 상세 화면 진입 시 이미지의 위치가 자연스럽게 연결되는 **Shared Element Transition** 효과 고려.

### [2026-01-10] v0.1.7 - 피드 리스트 및 캘린더 기능 구현
- **작업 내용:**
  - **피드 캘린더(Calendar) 기능:**
    - 월별 달력 뷰(View) UI 구현 및 발병 이력이 있는 날짜에 인디케이터(Dot) 표시.
    - 특정 날짜 선택 시 해당 일자의 음식/증상 기록을 불러오는 필터링 로직 적용.
  - **피드 리스트 증상 표시 기능:**
    - 음식 카드 내 질병명 및 발병 횟수를 직관적으로 보여주는 오버레이(Overlay) UI 구현.
    - 다중 질병 데이터를 처리하기 위한 리스트 구조 적용.
  - **기록 피드백(Toast) 구현:**
    - 저장 완료 시 화면 흐름을 방해하지 않는 토스트 메시지 및 실행 취소(Undo) 기능 적용.
  - **홈 퀵 로그(Quick Log) 프로세스:**
    - '아파요' 버튼 클릭 시 별도 팝업 없이 즉시 기록되는 Non-blocking 로직 적용.
- **비고:**
    - **발병 연동:** 증상 기록 시점 기준 24시간 내 섭취 음식을 자동 매핑하도록 정책 수립.

### [2026-01-09] v0.1.4 - 기록 프로세스(Logging Flow) UX/UI 설계
- **작업 내용:**
  - **음식 기록 화면(Food Logging) UI 확정:**
    - 사진 등록, 메뉴명 입력, 태그(맛/온도/상황) 선택 칩(Chips) 인터랙션 설계.
    - '추천 재료' 토글(Toggle) 및 동적 태그 추가 로직 정의.
  - **증상 기록 화면(Symptom Logging) 구조 정의:**
    - 음식 기록과 톤앤매너를 맞추되, 사진 대신 통증 레벨/증상 아이콘 위주로 변형.
  - **기록 완료 피드백(Feedback Modal) 디자인:**
    - 기록 성공 시 노출되는 'One-Point' 디자인의 심플 모달(Success State) 구현.
    - 음식/증상 기록 공통 컴포넌트화 및 텍스트 분기 처리 로직 수립.
- **비고:**
    - **입력 폼 확장성:** 기록하기 화면의 '추천 재료' 리스트 및 태그 선택 시 확장/축소(Collapse/Expand)되는 UI의 일관성 유지 방안 모색.
    - **재료 태그 인터랙션:** 터치 시 **반전(Touch Feedback)** 후, 물리적 이동 궤적 대신 자연스러운 **리스트 레이아웃 애니메이션(Fade/Scale)**을 통해 상단 삭제 및 하단 추가 처리.
